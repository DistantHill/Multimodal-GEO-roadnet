## 工作量与预算

全部 24 轮逐组确认：P0 解码 301,151 次，P1 解码 62,953 次，P2 解码 19,696 次，
最终解码次数下降 93.46%。
P2 的 157 个交叉口对全部命中缓存；48,051 条边界片段完全不读点。
对应解码点数为 3,670,928 / 742,367 / 226,845，亦逐轮一致。
P1、P2 都只遍历一次 72,834 行标量元数据。独立诊断确认 5,087 条片段的两个端点
为同一交叉口，在标量阶段形成原有问题；实际可拟合候选为 19,696 条。
因此 P2 相对全部输入的解码比为 0.2704，含义是可拟合候选各解码一次，
不能把 0.2704 误称为每个候选只解码四分之一次。

独立诊断的累计弧长准备次数：P0 与 P1 各 43,257 次，P2 为 19,696 次；
三组最终中心线等距重采样各 428 次，单独计数。该诊断带额外计数，
三条诊断耗时均不纳入正式性能统计；三份完整输出摘要仍与正式测量一致。
诊断容器实际 `memory.max=4294967296`、`memory.swap.max=0`、
`cpu.max=200000 100000`，与指定限制一致。

缓存最多使用原 16 MiB 工作区的一半。计数包括 NumPy 实际拥有的缓冲区、数组对象、
槽位数据类与列表容量；采样矩阵按剩余预算分块。缓存首次或中途超限时全部释放，
继续从 DuckDB 读取。单列矩阵本身超预算时禁用缓存并保留既有至少一列行为。
16 MiB 只约束受控缓存与采样矩阵，不是整个 Fitting 的内存上限。

正式测量中 P2 最大缓存为 2,623,472 B（2.50 MiB），最大采样矩阵为 14,099,520 B，
两者同时最大值为 16,722,992 B，小于 16,777,216 B。所有组均没有单列超预算情况。

它们不能解释为纯 Fitting 阶段峰值，也不把 RSS 与控制组峰值互相替代。
