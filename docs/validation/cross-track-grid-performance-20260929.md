# cross_track 网格性能定位与速度筛选

本次针对 Refine `f76bab1e-1af1-45d0-9368-cc2a67aceb04` 的 `(0, 0)` 网格。
原始记录： /data/tmp/road-network/logs/20260929_150225_123270_pid-462811_log.txt 。
验证使用 /data/workspace/Multimodal-GEO-roadnet/services/pipeline/config/pipeline.toml ，
仅复测一个网格，未运行 Pipeline 全量测试或冒烟测试。数据库使用只读事务，不创建 Detect Run。

## 原因与测量边界

日志中的 `111,647` 是线段数，`68.4s` 是仍在运行时的累计时间，包含读取、准备、求交及输出等待，
不是已完成的 10 万线段对求交耗时。原日志到 16.1 秒仍显示读取中，到 21.6 秒才显示该格线段数。

对同一格单独读取：数据库查询、网络取回和点列转换合计 8.411 秒，线段构造 0.294 秒，
拼接、去重和排序 0.044 秒。没有把数据库服务端执行、客户端解码进一步拆开，也没有清理数据库缓存。

原有索引已按线段建立，不会在命中轨迹后重新展开完整轨迹；但同格内跨子轨迹配对仍过多。
直线筛选后有 94,439 条线段，588,473 条网格归属记录；格内原始无序组合共 887,755,293 对
（尚未排除同子轨迹和跨格重复），761 条长线段另进入逐对 Python 循环，溢出配对空间估计 71,868,079。
最终实际送入 NumPy 的是 386,535,928 对。

## 保持原结果的性能优化

保留现有空间网格，增加以下筛选：

- 按方向角分为 10° 桶，仅查询可能满足原夹角条件的桶对。边界留保守余量，最终沿用原 NumPy 判断。
- 在桶对内部按包围盒下界排序，选择重叠区间更少的轴，批量枚举区间命中，检查另一轴及原夹角条件。
- 跨格仍按最小公共格归属去重；同一 Run 的子轨迹身份决定配对方向，不因车辆相同而丢弃跨子轨迹关系。
- 长线段查询排序后的包围盒下界，使用有界数组批次，移除逐线段对 Python 循环。
- 合并稀疏候选批次后，才复制坐标并调用原逐对 NumPy 内核。

在加入新的速度条件之前，使用同一批已读取的线段、批大小 65,536：

| 指标 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 建索引 | 0.991 s | 1.326 s |
| 候选查询与枚举 `candidate_s` | 50.473 s | 3.464 s |
| 坐标高级索引复制 `gather_s` | 21.980 s | 0.304 s |
| NumPy 求交 `kernel_s` | 10.060 s | 0.812 s |
| 实际内核输入对数 | 386,535,928 | 4,497,241 |
| 精确交点数 | 1,701,155 | 1,701,155 |
| 本段计算墙钟时间 | 84.009 s | 6.014 s |

该墙钟时间从直线筛选开始，包括建索引、候选生成、坐标复制、求交及交点来源数组构造，
不含数据库读取、候选业务字段构造、跨格合并和结果写出。两轮为单进程复测，不等同原日志的四线程运行环境。
此对照未使用独立 CPU/内存控制组，不能作为固定资源下的吞吐验收。

将全部结果按原始线段索引对排序，逐元素比较 `x`、`y`、两侧线段索引以及两侧完整五字段端点身份，
1,701,155 个交点全部完全一致。不同来源对即使坐标相同仍分别保留。

另一次使用最终基准入口、阈值设为 0（该格没有负速度线段）的批大小对照，包含候选业务字段及逆投影构造，
不包含写出；读取一次后按下列顺序复用线段：

| 批大小 | 计算及候选构造 | 输入对数 | 交点数 | 进程累计峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 10,000 | 6.795 s | 4,497,241 | 1,701,155 | 231,497,728 B |
| 100,000 | 7.051 s | 4,497,241 | 1,701,155 | 277,639,168 B |
| 500,000 | 6.654 s | 4,497,241 | 1,701,155 | 512,823,296 B |

各档只测一次，时间差不足以支持修改默认批大小；500,000 档增加了峰值内存。
峰值为同一进程的累计高水位，后续档位可能包含前一档分配器保留的内存。
这轮数据库读取 9.295 秒、线段构造 0.383 秒、排序 0.048 秒，未计入表中的计算时间。

## 新增平均速度条件

用户追加要求：线段起点和终点速度的平均值小于 20 时不进入相交计算。
新增算法参数 `detect.cross_track_min_avg_speed = 20.0`，读取原始 `speed` 数值，不额外换算单位；
实际条件为 `(speed_start + speed_end) / 2 >= threshold`，等于阈值保留。
阈值要求有限且非负。三个随仓库提供的 Pipeline 配置均已补充，外部完整配置也需要添加此键。

内存网格和直接数组路径在建索引前筛选；溢写路径在精确求交前筛选；Parquet 路径在构造直线关系时筛选。
网格线段增加 `end_speed` 列，Parquet 通过子轨迹内的 `lead(speed)` 获取终点速度，均不使用整条轨迹平均速度。
输出候选原有 `speed` 字段继续保存来源起点速度。

该格复测：111,647 条原始线段中，106,360 条不满足速度条件；同时满足直线和速度条件的有 5,114 条。
实际内核输入为 0 对，交点为 0。**这是新增筛选条件导致的结果变化，不能称为保持结果的加速。**

| 候选对批大小 | 计算及候选构造 | 交点数 |
| --- | ---: | ---: |
| 10,000 | 0.112 s | 0 |
| 100,000 | 0.110 s | 0 |
| 500,000 | 0.107 s | 0 |

这轮数据库读取 7.916 秒、线段构造 0.391 秒、排序 0.045 秒；筛选后约 0.11 秒，
故该格剩余耗时主要来自读取。本轮没有精确内核输入，不能据此判断三个内核批大小哪个更优，默认 65,536 不变。
同一基准进程累计峰值 RSS 为 231,542,784 B；这是单进程观测，不是整个 Pipeline、全部 worker 和数据库的
2.5 GB 总峰值验收。原配置中多个 DuckDB 实例各有内存额度，本次未改变这些额度。

## 新的日志字段

每格运行中和结束时输出计数及累计时间，生成器计时只包围 `next()`，排除消费者暂停时间。

| 字段 | 含义 |
| --- | --- |
| `read_s` | 获取点批次，包括查询等待、传输及当前读取器的列转换 |
| `segment_s` | 构造线段、缓存或追加到溢写关系 |
| `sort_s` | 拼接、去重、排序或溢写关系完成 |
| `prepare_s` | 内存路径直线/速度筛选、坐标数组准备及子轨迹顺序整理 |
| `index_s` | 原空间网格建立；查询时的区间排序计入 `candidate_s` |
| `pre_intersection_s` | 上述五项合计；求交前准备时间 |
| `candidate_s` | 空间候选查询、区间枚举、配对归属与夹角过滤、批次合并 |
| `gather_s` | 精确内核输入的坐标/方向角数组复制；溢写路径还包含块读取与列准备 |
| `kernel_s` | 原 NumPy 精确求交调用 |
| `output_s` | 交点来源及候选业务数组构造，加主线程本格暂存写出；`write_s` 为其中的写出部分 |
| `queue_s` | worker 提交结果到有界队列的等待；与主线程写出可能重叠，不能相加推算墙钟时间 |
| `pair_count` / `hit_count` | 实际内核输入对数 / 精确交点数 |
| `straight_segments` / `eligible_segments` | 仅满足直线条件 / 同时满足直线和速度条件的线段数 |
| `speed_rejected_segments` | 未满足速度条件的原始线段数，和直线剔除可能重叠 |
| `bbox_query_pairs` | 内存路径区间查询后实际枚举的粗候选对数，包含随后被其他条件剔除的对 |
| `mode` | `reading`、`memory` 或 `spill` |

全部网格结束后的跨格去重、排序和写出单独记录为 `cross-track finalize output_s=...`。
本格的 `output_s` 不包含后续 Detect PostgreSQL 持久化，多个 worker 的耗时不能直接相加作为总墙钟时间。
超出线段缓存预算的溢写路径仍按块配对；本次 111,647 线段走内存路径，未验证大规模溢写吞吐。

## 复现入口与回归

单格只读基准入口是 `python -m track.v2.diagnostics.bench_cross_track_grid`。
使用环境变量 `PIPELINE_CONFIG_PATH` 指向上述全量配置，`--refine-id f76bab1e-1af1-45d0-9368-cc2a67aceb04 --grid 0 0`；
`--batch-sizes 10000 100000 500000` 比较批大小，`--min-avg-speed 0` 可复测非负速度数据的原结果规模。
入口读取一次线段，多轮复用列数组；输出 JSON 到标准输出，临时 DuckDB 数据在退出时清理。
它消费候选结果但不写入正式结果关系，不创建数据库 Run。

回归覆盖：格边界、多格配对去重、溢出配对、不同子轨迹同车辆、同子轨迹排除、零长度线段、
方向角桶边界及巨大方向角、多个批大小与角度范围，和独立全配对几何结果比较；
10,000 条同方向线段验证在配对枚举前剔除；计时验证不包含消费者等待。
平均速度在内存、溢写、Parquet、直接数组四条路径验证 `0/40`、`40/0`、`20/20` 保留，
`0/39`、`39/0`、`19.9/20` 剔除。


`make test` 指 Compose 配置检查、Backend pytest、Pipeline pytest 和人工检查工具测试套件，
不等于 `make pipeline-full-test` 的完整 Pipeline 数据链路。Pipeline 测试工厂以
 /data/workspace/Multimodal-GEO-roadnet/services/pipeline/config/pipeline.toml 为基础，
各用例按需覆盖参数或生成临时配置。没有调用 `make pipeline-smoke-test` 或 `make pipeline-full-test`。

最终 `make test` 通过：Compose 检查 18 项通过，Backend 107 passed / 2 skipped，
Pipeline 与人工检查工具 1,279 passed / 72 skipped（78.81 秒）。12 条警告来自已有 Rasterio 仿射运算弃用提示。
