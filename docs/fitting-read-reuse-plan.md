仓库支持分两步减少 Fitting 的重复读取：先以元数据筛选、按交叉口对共享一次几何准备，
再在当前交叉口对内有界复用几何和累计弧长。三个变体仍分别计算中位长度、采样网格、
中位坐标和输出。本计划不把三个拟合结果合成一次计算。

## 2 必须处理的约束和设计变化

### 2.1 三个变体保持独立语义

合并、正向、反向分别应用 `min_clips_per_pair`；各自的中位长度决定采样数量。
例如正反方向各一条片段、门槛为二时，合并可以拟合，两个方向都必须跳过。
不能复用合并变体的采样网格或最终中心线来代替两个方向。
反向结果仍需交换端点、反转输出点并交换正反计数。

保留 `fit_centerlines(clips, config=...)` 和 `fit_centerline_variants(clips, config=...)`
的调用形式、返回类型及 `bundle.combined == fit_centerlines(...)` 的行为。

### 2.2 报告和顺序保持当前含义

合并变体的 `input_clip_count` 包含边界片段；方向变体只计类型正确、端点完整且不同、
方向匹配的片段。`eligible_clip_count` 在几何校验之前计数。
端点有效但几何无效的交叉口对仍计入 `connected_pair_count`，可能同时产生片段问题和
`insufficient_clips`。不能按最终有效片段数提前删除该交叉口对。

片段问题按原始 `ordinal` 顺序输出，再追加按交叉口对排序的拟合问题；
每条中心线的来源按 `clip_id` 排序，相同键保留原始顺序。
三个结果各自按交叉口对排序，最终持久化仍按合并、正向、反向三组排列。

### 2.3 几何长度和浮点运算保持当前定义

`distance_m` 不能替代 `_xy_polyline_length()`。现有测试会将 `distance_m=200`
与实际 125 米几何组合，拟合仍使用实际几何长度。
同时，原始几何长度包含所有线段，而 `_deduplicate_xy()` 会按 `_EPS` 删除短段；
用于中位长度的数值和用于插值的累计弧长必须分别保留。

保留原规范方向、去重阈值、求和顺序、`np.linspace`、`np.interp`、精确中位数及末段采样规则。
目标是与参考实现逐字段、逐元素完全一致；出现差异先定位，不自动改为容差验收。

### 2.4 超预算继续使用 DuckDB

架构和测试已移除自写 `DiskSequence`、临时磁盘暂存与 `np.memmap`。
因此修正先前的磁盘暂存建议：几何缓存容纳不了当前交叉口对时，清空缓存，
继续使用现有 DuckDB 关系重复读取。引擎内置的临时外存策略保持现状。
不新增 Python 全局几何缓存或自己的可恢复中间文件。

### 2.5 变体执行顺序是本轮明确的设计变化

历史架构 Q111 把拟合计算复用留到后续，先保持三个流程；不能将本轮优化
描述为仅修改读取批量。本计划将调度从“全部合并，再全部正向，再全部反向”改为
“一个交叉口对内分别完成三个变体”，共享准备而保持各变体数值算法独立。
用户的后续实施授权已覆盖本轮变化；架构现行补充说明与历史 Q111 原文并存。
实现完成与功能、性能验收分别记录。

### 2.6 工作区预算和运行配置

首版复用现有 `_FIT_BLOCK_BYTES=16 MiB` 的内部工作区预算：最多一半用于保留几何缓存，
采样矩阵使用剩余预算。缓存没有命中时，矩阵沿用原预算。8 MiB 是内部预算分配，
不是新增的源码可调默认值。基准测试需检查这种分配是否增加分块次数或造成耗时回退。

此预算只计受控保留的缓存数据与采样矩阵，不代表整个 Fitting 的内存上限。
单片段解码、数值准备临时数组、长度向量、来源标识符和最终输出另行测量。
现有算法在单个采样位置的矩阵已超过预算时仍需至少一列；本轮不借缓存优化改变该行为，
这种情况禁用缓存，并记录实际矩阵大小，不能宣称矩阵始终小于 16 MiB。

首版不新增配置字段。若基准证明需要独立、受支持的缓存调参项，应放入 `runtime`，
同步完整 TOML、加载器、类型、接线和快照测试。不能直接加入 `FittingConfig`：
当前完整快照将 `fitting` 全部归入 `semantic_config`，缓存预算应属于执行配置。
实际生产资源约束仍沿用现行架构：容器无硬内存上限，6,000,000,000 B 为日志观测阈值。
本轮 2 核、4 GiB 仅作为阶段基准的隔离条件，不改变生产约束。

## 3 第一步 共享筛选和几何准备

### 3.1 新增最小读取接口

在 `ClipRelation` 增加有界的 `iter_fitting_metadata()`，按 `ordinal` 读取
`clip_id`、`clip_type`、两个交叉口端点和 `point_count`，不查询片段点，不构造 `TrackClip`。
接口要求关系已完成校验，读取退出或异常时关闭自己的游标。

增加仅供拟合使用的配对迭代器，返回原始 `ordinal` 与片段，筛选
`between_intersection`、端点完整且不同，按 `clip_id,ordinal` 排序。
复用现有点批次读取及解码，不修改 `__iter__()`、`iter_pair()` 等已有接口的输出。

普通 `Sequence[TrackClip]` 使用适配器，沿用已经存在的对象引用，不再分三次建立分组。
生产 DuckDB 路径只保留交叉口对级汇总，不把全部元数据复制成 Python 对象表。

### 3.2 元数据阶段

遍历一次标量元数据，分别累计三个变体的输入数、候选数和交叉口对集合。
边界片段直接略过几何读取；未知类型、缺失端点、相同端点按现有规则形成问题。
方向资格依据片段类型和端点确定，不能把这些问题无条件复制给方向变体。

### 3.3 按交叉口对准备一次

按规范交叉口对顺序读取候选几何，执行现有 `_orient_clip()` 校验与方向规范化，
形成当前对的有效来源标识符、原始几何长度、方向标记和原始顺序。
同一无效片段的问题分配给合并及符合方向资格的那个变体。
完成该对校验后，各变体分别检查最小数量和计算中位长度。

第一步不保留几何缓存，准备后的几何及时释放；采样仍通过 DuckDB 配对迭代器读取。
为拟合内核传入已经准备的统计，消除三个变体各自的全量准备及长度统计重读。
所有来源只经过同一数值内核；不长期维护两套拟合算法。

### 3.4 组装结果与进度

三个结果分别累积中心线和问题。计算完成后按第 2.2 节恢复输出顺序，
复用现有反向结果转换并组装 `CenterlineFitBundle`。
元数据准备和交叉口对拟合分别有心跳范围，单位为片段和交叉口对。
采样循环不覆盖外层计数；三个拟合变体的执行进度不再伪装成三次全量解码。
更新现有严格心跳测试，使其验证新的真实工作量、计数单调性和作用域恢复。

## 4 第二步 当前交叉口对内复用几何

在第一步配对准备期间，尝试缓存规范方向下的去重 XY 和标准化累计弧长。
仅保留插值所需的最小数据，不缓存完整 `TrackClip`、经纬度和点标识符数组。
原始几何长度仍单独保留，不用去重长度替代。

缓存覆盖当前对的有效几何时，三个变体通过方向选择复用这些数据，
分别生成自己的采样网格；所有采样分块也复用相同的准备数据。
按既有表达式进行 `np.interp` 和聚合，保持矩阵行序、数值精度与方向转换。

缓存准入同时核对数组实际字节数和容器开销。超预算时释放当前对的全部缓存，
后续采样走 DuckDB 读取；不保留无界部分缓存，不建立全局淘汰策略。
已准备的标量统计继续复用。交叉口对结束或任何异常退出时释放缓存。

缓存命中的目标是每个可拟合片段只在准备时解码一次；超预算组允许重复读取。
以全部 72,834 条输入为分母时，过滤边界后的比值会低于一，不能与
“可拟合片段解码一次”的口径混用。分开记录全部输入、候选、有效片段和重建数量。

## 6 验证矩阵和验收标准

### 6.1 功能与资源行为

1. 内存序列和 DuckDB：空输入、仅边界、双向、仅单向、多交叉口对、乱序输入、
   同键稳定顺序与最小片段数独立判断。
2. 问题和报告：未知类型、缺失或相同端点、无效或零长度几何、全部无效的交叉口对、
   混合问题顺序、冲突几何导致退化中心线。
3. 数值：奇偶片段数、原始距离与几何长度不一致、重复点、阈值附近短段、
   正反片段长度明显不同、短末段、多个采样分块；与现有独立参考中位数逐元素相等。
4. 缓存：刚好容纳、首次即超预算、中途超预算、多次拟合同一关系、只读输入数组，
   大对回退不会保留上一对缓存；以读取计数验证结果复用，而非只检查内部函数名。
5. 生命周期：读取游标异常或提前关闭、缓存准备或采样异常、完整 Run 回滚和完成状态，
   Fitting 结束后 Clip 关系仍可供来源清单及 Network 所属上下文使用。
6. 持久化：三个变体的全部字段、来源顺序和标识符映射一致，来源清单写入仍不解码点。
7. 保留禁止自写磁盘暂存的测试，运行相关定向测试后执行 `make test`。

### 6.2 真实样本性能

使用原 72,834 条 Clip 样本，首先固定 relation batch 为 1024，分别测基线、P1、P2；
再固定为推荐的 32768 做同样对照，防止把调参收益算作复用收益。
每组预热一次、至少三次测量，交错并平衡执行顺序；每轮独立进程，固定镜像摘要，
记录源码、完整配置和数据摘要。

分别记录 Fitting 计算、Clip 构建、独立输出校验、持久化耗时，不能合并口径。
完整数值校验不计入性能计时；单独记录带校验进程的常驻内存集大小（RSS）与
控制组峰值，不把 RSS 当作控制组峰值。
额外记录各方向重建量、点查询次数、累计弧长准备次数、缓存命中和回退对数、
保留缓存字节数、最大采样矩阵以及异常路径资源释放。

验收先要求所有输出、报告和顺序严格一致，再检查解码和读取量下降。
P2 只有在配对测量中稳定优于 P1、且资源变化符合记录预算时才作为默认实现；
如缓存挤占矩阵预算造成回退，应修改分配算法或保留 P1，不宣称 P2 已有收益。
不预设未经测量的提速百分比，也不将阶段改进解释为完整 Pipeline 提速。

新结果写入数据库 `tmp` 的独立实验标识，关联旧实验，不覆盖旧数据；
在比较 P0、P1、P2 时记录准备状态和缓存状态，保证统计可区分。

## 7 查询与数据安全范围

拟合元数据与配对查询只操作当前 DuckDB Clip 关系的标量身份和顺序，
片段内点按 `clip_ordinal` 等值关联，没有空间范围或距离谓词；空间索引不适用。
实施时对实际新增或修改的查询逐项记录内容哈希与具体理由，按项目 SQL 检查要求存档。
不修改 PostgreSQL 权威源、已完成 Run 或已发布 Parquet，不新增数据库迁移。

## 8 检查结论

实现机制已由仓库的标量与几何分离、稳定配对读取、只读数组、独立数值参考和
现有生命周期支持。需要明确变更的是三个变体的执行顺序和进度报告；
必须避免的冲突是重引自写磁盘暂存、混用方向统计、改用 `distance_m`、丢失无效配对报告，
以及把几何缓存额外叠加到采样预算而宣称总内存不变。
本轮 72,834 条输入的 157 个交叉口对全部命中缓存，P2 的最大缓存为 2.50 MiB；
当前 batch=1024 的 Fitting 中位耗时由 P0 的 35.675 秒降至 P2 的 5.677 秒。
24 条对比与三条独立诊断完整结果一致，`make test` 全部通过；结论限本轮阶段样本，
不代表精确 26M 全链路验收完成。
