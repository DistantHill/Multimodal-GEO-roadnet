# GPS 点栅格 MVP Reviewed Plan

## 1. 审查结论

状态：`READY_FOR_IMPLEMENTATION`

本计划已经根据审查意见和用户确认修订。当前阶段只形成实施计划，不修改代码、数据库结构或运行时数据，也不执行生产数据任务。

进入实现时，栅格模块与检测阶段（Detect）共享同一套输入语义：指定精炼阶段（Refine）运行的保留点（kept points）和注入点（injected points）都必须包含在输入中。运行时仍需显式提供 `refine_id`、研究区域或自动范围策略以及输出位置；这些属于单次运行输入，不是设计阻塞项。

## 2. 已确认范围

### 2.1 输入

- 输入与 Detect 使用的逻辑点流一致。
- 对指定 `refine_id`，输入包括：
  - `kept_trajectory_points` 中属于该 Refine Run 的保留点；
  - `injected_points` 中属于同一 Refine Run 的注入点。
- 保留点通过 `source_row_key` 关联原始点表，取得几何和既有字段；注入点直接使用该 Refine Run 持久化的坐标与身份。
- 两类点使用同一 `processing_srid`。该坐标参考系（coordinate reference system，CRS）继承自 Refine Run 的持久化空间上下文，不另行猜测或覆盖。
- 注入点仍按离散点参与计数。模块不连接相邻点、不栅格化线段，也不再次执行精炼或检测逻辑。
- 输入范围以 `refine_id`、源表、筛选区域和相关运行元数据共同标识；不得混入其他 Refine Run 的注入点。

### 2.2 本轮必须完成

- 有界批量读取上述统一点流。
- 构建并持久化统一的 `GridSpec`。
- 普通点计数 `raw`：每个接纳点只向一个栅格单元贡献 `1`。
- 从完整逻辑计数栅格的非零唯一单元计算全局 Q95。
- 使用 Q95 截断和平方根映射生成 `uint8` 灰度图。
- 生成单波段原始计数 GeoTIFF、单波段灰度 GeoTIFF，以及按需物化的三通道灰度复制结果。
- 使用滑动窗口生成 RGB PNG、有效性 mask 和切片索引。
- 保存来源、CRS、变换、配置、统计摘要和产物身份信息。
- 提供合成测试以及一块经授权真实样本的轻量验证入口。

### 2.3 本轮不做

- `unique_vehicle_cell` 及其车辆身份归并语义。
- 非 `none` 的点核、方向通道和其他尚未确定的归一化算法。
- 前端、模型训练、YOLO 推理、检测结果回写和全量生产运行。
- 新建分布式计算平台或改变 Refine、Detect 的既有语义。

未来能力不作为本轮接口或验收标准的必备内容；实现中不需要为未确定语义建立提前抽象。未知选项若被传入，应明确报错。

## 3. 仓库接入方案

### 3.1 输入复用

优先复用 Detect 已有的统一查询和空间上下文：

- `build_stream_all_sql(..., kept_table="kept_trajectory_points", refine_id=...)` 所表达的保留点与注入点组合语义；
- Refine Run 中持久化的 `source_srid`、`processing_srid` 和 `projection_config`；
- 服务端命名游标（server-side named cursor）和有界 `fetchmany()` 读取方式；
- 已有来源行身份、`point_kind`、`source_row_key` 和注入点 `id`。

栅格聚合不依赖轨迹顺序，因此读取器可以只投影实际需要的字段，但必须保持与 Detect 相同的行集合和 Refine Run 隔离语义。应通过测试比较两条输入路径的点身份集合或稳定摘要，防止后续查询演进造成分叉。

### 3.2 分块与边界归属

首选路径是通过一个服务端命名游标顺序读取完整逻辑输入，每个源点只读取一次，再按其全局栅格索引累加。该路径不需要用空间窗口重复读取点。

如果实现需要采用空间窗口读取：

- 点读取窗口的 `overlap` 固定为 `0`；
- `overlap=0` 只消除具有面积的重叠，不能单独解决共享边界重复，因为现有窗口查询对最小值和最大值均使用闭区间；
- 非末端窗口必须采用半开范围，或为每个点计算全局栅格索引并指定唯一规范归属者；
- 最东和最南外边界仍按 `GridSpec` 规则排除，不能通过 clamp 堆入边缘单元；
- 验收必须包含恰好落在相邻窗口共享边界上的点。

训练切片的图像 `overlap_px` 与点读取窗口的 `overlap` 是两个独立参数。前者默认可为 `256`，后者在采用空间窗口读取时固定为 `0`，不能共用配置键。

### 3.3 依赖

实现阶段将 Rasterio 作为 Pipeline 的显式依赖加入项目依赖和锁文件，并验证容器构建环境所需的 GDAL 运行库。Pillow 继续用于 PNG 输出；NumPy 用于计数、分位数和灰度映射。

依赖变更的验收包括：

- Pipeline 镜像能够可复现构建；
- 在容器内能够导入 Rasterio 并创建、回读带 CRS 和仿射变换的 GeoTIFF；
- 锁文件和镜像不依赖开发机上未声明的系统包。

## 4. 网格与坐标规则

MVP 只接受经过验证的米制投影 XY，输出为 north-up、无旋转、方形像素栅格。`west` 和 `north` 表示左上角外边界，分辨率为 `r > 0`：

```text
east  = west  + width_px  * r
south = north - height_px * r

col = floor((x - west) / r)
row = floor((north - y) / r)

有效世界范围：[west, east) × (south, north]
```

GDAL 六参数为 `(west, r, 0, north, 0, -r)`。元数据必须明确参数顺序，不能与 `Affine(a,b,c,d,e,f)` 的构造顺序混用。

显式 `GridSpec` 对越界点进行统计并排除。自动范围使用固定锚点和全局整数单元索引推导，必须覆盖单点、单行、单列以及位于网格线上的样本。

整数单元中心使用 `(col + 0.5, row + 0.5)`；已经采用左上外边界原点表示的连续图像坐标不再增加半像素偏移。

## 5. 计数与归一化

### 5.1 原始计数

对所有通过来源、有限值、CRS 和范围检查的输入点：

```text
C[row, col] += 1
```

必须满足：

```text
sum(C) == accepted_point_count
```

该等式只针对唯一原始计数栅格，不对具有重叠的训练切片求和。累加和求和使用足够宽的整数；写出 `uint32` 前检查单元最大值，超出范围时明确失败或使用已支持的更宽类型，不能回绕。

### 5.2 全局 Q95

统计对象是完整逻辑计数栅格中所有 `C > 0` 的唯一有效单元，每个单元权重相同：

```text
Q = quantile(nonzero_unique_cells, 0.95, method="linear")
```

不得按读取批次或训练切片分别拟合，不得平均局部分位数，也不得因训练切片重叠重复计入同一栅格单元。

### 5.3 灰度映射

```text
clipped = min(C, Q)
z = sqrt(clipped / Q)
I = uint8(floor(255 * clip(z, 0, 1) + 0.5))
```

`count=0` 映射为 `0`；`count=1` 不被隐式过滤。若非零单元为空，归一化状态为 `empty`、`q95=null`，输出全零，不执行除零。

## 6. 输出与切片

运行产物写入 `DATA_ROOT` 下按运行身份隔离的目录，不覆盖不同参数的既有结果。最小产物包括：

```text
run_manifest.json
grid.json
count_metadata.json
normalization.json
metrics.json
raw_count.tif
gray_uint8.tif
rgb_uint8.tif              # 可按配置选择是否物化
tiles/images/*.png
tiles/masks/*.png
tiles/tiles.csv
```

真实计数零值是有效数据；图外 padding 是无效区域。两者都可以显示为黑色，但 padding 必须由显式 mask 和有效尺寸区分，不能使用 `nodata=0` 混淆。

训练切片默认参数为：

```text
tile_size_px = 1024
overlap_px = 256
stride_px = 768
edge_mode = pad
```

切片只裁剪和补边，不调整尺寸、不重采样、不重新拟合 Q95。PNG 的地理定位由 `tiles.csv`、`grid.json` 和运行清单共同提供。

## 7. 配置与运行状态

遵循项目的配置集中化规则：

- 分辨率、计数模式、归一化方式、切片大小、内存预算和输出策略进入已解析配置快照；
- `refine_id`、研究区域和输出目标属于单次运行输入；
- `processing_srid` 继承指定 Refine Run，不允许为复用运行另行覆盖；
- 语义配置与执行配置分别记录，执行批大小变化不得改变像素结果；
- 运行状态至少区分 `running`、`complete` 和 `failed`，只有全部必需产物完成并通过一致性检查后才能标记为 `complete`；
- 清单与日志不得包含密码或完整含密钥的数据源名称（data source name，DSN）。

## 8. 资源保护

在分配计数栅格前计算 `width_px × height_px`，并估算计数数组、灰度块、分位数统计、RGB 写出缓冲区和文件输出的内存及磁盘需求。

配置明确的 `max_cells` 和内存预算（memory budget）。超出上限时必须在大数组分配前失败。分批读取点不等于整个流程已经支持外存计算；如果本轮只支持受限范围，应在运行报告中明确能力边界。

## 9. 验证计划

### 9.1 合成验证

- 6 点 fixture：原始计数总和为 `6`，非零计数为 `[1,1,4]`，线性 Q95 为 `3.7`，对应灰度为 `255/133`。
- 将相同输入拆成不同批次并改变批次顺序，原始计数数组保持一致。
- 验证 NaN、Inf、空输入、单点、单行、单列和四侧边界。
- 验证相邻空间读取窗口共享边界上的点只计数一次。
- 验证大合成计数的整数精度和写出范围检查。
- 验证 `count=0`、空 Q95、舍入和单调性。
- 验证 R、G、B 三通道逐像素等于灰度。
- 使用 6×5 原图、4×4 切片、1 像素重叠验证四个窗口的覆盖、有效尺寸和 mask。
- 验证局部切片坐标、全局像素坐标和世界坐标的两条换算路径一致。

### 9.2 仓库接入验证

- 指定同一 `refine_id`，证明栅格输入与 Detect 输入具有相同的保留点和注入点身份集合或稳定摘要。
- 证明其他 Refine Run 的注入点未混入。
- 证明读取批大小不改变输出。
- 证明 GeoTIFF 回读后的 shape、dtype、CRS、transform 和像素数组与写出前一致。
- 验证失败运行不会覆盖完成产物或标记为 `complete`。

### 9.3 真实样本验证

只对经授权的小区域执行只读输入与文件输出验证，记录 `refine_id`、区域、点数、接纳与排除统计、栅格尺寸、Q95、耗时、峰值内存和产物大小。

该验证只证明输入映射、计数、坐标和文件链正确，不证明 YOLO 效果或全量生产吞吐。

## 10. 实施顺序

1. 增加并锁定 Rasterio/GDAL 依赖，完成容器内最小 GeoTIFF 冒烟测试。
2. 建立栅格模块的配置、`GridSpec` 和运行产物结构。
3. 复用 Detect 输入语义，完成单游标、有限字段的点批次读取。
4. 实现原始计数、边界统计、整数范围保护和总和守恒检查。
5. 实现全局非零单元 Q95、平方根灰度映射和空场景处理。
6. 分块写出计数、灰度和可选 RGB GeoTIFF。
7. 实现训练切片、padding mask、索引和坐标回写。
8. 完成合成测试与仓库接入测试。
9. 在获得具体 `refine_id` 和样本区域后执行轻量真实样本验证。

完成第 8 步后可进入真实样本验证；真实样本验证完成前，不得声称图像效果、模型效果或生产规模性能已经通过。
