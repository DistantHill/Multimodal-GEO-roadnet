## 1. 背景与问题

用户需要在开发中高频修改参数、按时空范围运行 Detect，并快速索引与比较结果；不是讨论单个交叉口的匹配原理。
原先修改仓库 TOML 会产生频繁 Git diff。现有 Refine/Detect 已有 UUID、参数快照和产物目录，可复用；前端目录只显示 UUID 和时间，缺少实验语义与评价历史。
本次全量联合 DBSCAN 曾输入 28,989,419 点，turn 单独输入 292,505 点；这些是候选点计数，不是正确交叉口数量。
本规格独立于 frontend-work-spec.md 的回放设计，沿用其既有回放能力，不覆盖历史问答。

## 2. 目标与非目标

目标：一份仓库外本地 TOML、统一命令入口、实验结果页面。支持命名案例、多个命名方案顺序运行、独立评价存档与双实验对比（Q5–Q10、Q15、Q19）。
首版只支持现有 Detect 方案与代码版本，执行到 Detect 即评价（Q8、Q20）。
不做通用算法插件平台、参数网格搜索、网页启动或网页画区；不保存未提交代码或源码快照（Q18）。

## 3. 需求与使用场景

- 编辑同一份本地 TOML；配置当前选择、命名案例、参数方案与评价规则。后续网页及命令行共用解析、校验、快照机制（Q5、Q7）。
- 案例必须提供 source_table、带时区时间范围、GeoJSON 多边形文件或 bbox 两顶点二选一；缺失时报错（Q11–Q14）。
- GeoJSON 支持 Polygon/MultiPolygon；多个区域面取并集。QGIS 仅作编辑器，不要求插件传图层。源文件集中保存，运行归档实际副本。
- 一次启动多个显式命名方案，顺序执行、各自独立记录。单方案失败继续；共同输入无效则停止批次（Q9、Q17）。
- 真值为带唯一 ID 的交叉口面 GeoJSON。无真值允许运行，显示“未评价”；可后补真值评价已有结果（Q21、Q22）。

## 4. 方案与关键决策

已确认（Q12、Q26）：严格时空读取，不外扩。时间左闭右开，空间包含边界；裁点后保留离开/重入造成的轨迹断点。
已确认（Q25）：批次内相同输入和 Refine 参数只做一次 Refine；跨批次通过 refine_id 显式复用并检查归属。不增加全表数据指纹扫描。
已确认（Q18）：记录当前 commit、完整有效参数；不记录代码改动。
已确认（Q24、Q26）：匹配模式为中心距离、IoU、两者同时满足；模式所需阈值必填。使用适合案例的米制投影计算。
一对一匹配先最大化匹配数，再按距离模式最小化距离、按 IoU/组合模式最大化 IoU，并稳定处理并列。
保存 TP、FP、FN、Precision、Recall、F1；零分母标记不适用，不虚构 TN。重新评价新增记录，不替换历史（Q23）。

## 5. 接口、数据与架构影响

Pipeline 新增统一 experiment 命令入口，负责初始化、运行、历史列表、恢复参数、重新评价、重试存档及清理。长任务不在 Backend 请求内运行。
工作区位于 DATA_ROOT 下，集中 TOML、区域源文件、真值副本、日志和自动生成产物；不要求每次手工建文件。
算法在现有开发库执行。独立 roadnet_eval 库共用表保存案例版本、实验/批次 UUID、参数快照、交叉口几何、真值、评价历史与匹配明细，不复制海量候选点（Q15）。
评价存档不依赖运行库级联外键；开发库重置后仍能展示历史。存档幂等，失败保留原产物并标记待存档，支持单独重试。
清理须手动按实验执行，先验证完整存档并检查共享引用；保留其他实验使用的 Refine。清理后回放不可用，但历史地图与评价不受影响（Q6、Q16）。
Backend 增加只读实验列表、详情、评价历史和有界地图接口。网页显示案例、方案、commit、输入时空范围、执行时间、状态和指标；提供参数差异与双地图联动（Q19）。
默认只加载紧凑交叉口与真值/匹配结果，现存中间产物局部按需读取；不同案例或真值版本的对比明确标注差异。

## 6. 约束与非功能要求

统一管理入口，拒绝散落调试文件（Q7）。运行数据不入 Git；非敏感配置快照不包含密码。
使用现有服务边界与开发库，不自动清空现有数据库或启动全量数据测试。全量测试如另行授权，使用独立每 10 分钟日志监控，不在会话内轮询。

## 7. 验收标准

- 单份本地配置可执行多案例/多方案，无需修改受 Git 管理的参数文件。
- 测试缺失配置、非法几何、多边形/bbox、时间边界、轨迹离开重入；无越界原始点进入计算。
- 测试批次 Refine 共享、显式复用、失败继续；每次参数/几何快照不随草稿变化。
- 测试归档幂等、失败重试、清理共享保护及开发产物删除后历史地图可读取。
- 测试匹配最大基数、一对一、重复预测、空结果、无真值和重新评价历史。
- 测试列表筛选、参数差异、双地图联动与有界加载。
- make test、前端测试和构建通过；小型固定案例端到端验收。具体实测结果写实施报告，不把计划当成已通过。
