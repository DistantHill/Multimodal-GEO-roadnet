## 1. 背景与问题

用户要求整理全部配置及需要设定的参数，使 `src/**/*.py` 不再定义可调参数，
并已同意由加载器（loader）读取 TOML。当前代码事实（2026-09-19 核查）：

- Pipeline 已有 `services/pipeline/src/track/v2/config/pipeline.toml` 和
  `load_pipeline_config()`，但加载器仍以 Python 数据类默认值补齐 TOML 缺失项；因此
  TOML 尚不是唯一默认值来源。
- Pipeline 的阶段函数仍存在 `config=None` 后在函数内构造 `RefineConfig()`、
  `ClipConfig()` 等隐式默认配置的路径。
- Detect 的数据库查询上下文和状态回调等字段与真正可调参数共处一个配置数据类；
  Parser 默认值、数据库批量大小以及 `DATA_ROOT` 读取也存在重复或散落来源。
- `services/pipeline/src/pipeline/__main__.py`、Backend 数据库和健康检查代码仍直接读取
  环境变量并在 Python 中提供主机、端口、路径、超时等默认值。
- Backend 还在源码中设置查询行数上限、语句超时边界和依赖健康检查超时；Pipeline
  的资源预算、Detect 保护阈值、日志路径及工作区策略尚未全部进入现有 TOML。
- `services/pipeline/src/track/v2/manual_thin_benchmark/` 位于 `src/` 下，包含大量基准测试
  参数、验收阈值、冻结摘要和命令行默认值。它们是否属于本次“所有参数”仍待决定。

未检索到与本主题相同的既有 Spec；相关但不等同的历史设计包括
`pipeline-20m-memory-budget-spec.md` 中语义配置与执行配置的分类。

## 2. 目标与非目标

已给定目标：

- 可调配置与需要部署者设定的参数集中存放于 `config/` 下的 TOML 文件。
- 生产代码通过统一加载器读取、校验并传递配置。
- `src/**/*.py` 不再作为可调参数默认值的权威来源。

已确认范围包括 Pipeline 与 Backend 的生产运行源码，不包括
`manual_thin_benchmark/`（Q1）。只外置受支持的可调配置，协议版本、数据库结构版本、
枚举、数学固定量、错误码、冻结摘要及内部正确性常量保留在代码中（Q2）。设计确认
不代表实施授权。

## 3. 需求与使用场景

已确认前置约束（用户初始要求）：同意使用加载器读取 TOML。

已确认 Pipeline 与 Backend 分别使用完整 TOML，字段映射等专用 TOML 保持独立（Q3）。
配置文件放在 `services/pipeline/config/` 和 `apps/backend/config/`，不放在 `src/`；以后
Pipeline 调参只需查看服务顶层 `config/`（Q12）。
密码由 `.env` 提供（Q4），且 `.env` 仅保存秘密、Compose 宿主机挂载变量和服务 TOML
路径；其他非敏感运行配置进入 TOML（Q7）。单次运行输入继续由 CLI/API 提供，
`processing_srid` 等语义与执行配置只来自 TOML（Q8）。
仓库默认 Pipeline 配置使用 EPSG:32649（Q17）。
复用历史 Refine Run 时继续使用该 Run 持久化的投影，当前 TOML 值只用于新 Refine Run
（Q22）。

## 4. 方案与关键决策

当前设计树根节点为“配置集中化”。已确认的第一层决策如下：

1. 迁移 Pipeline 与 Backend 的生产运行源码，暂不迁移手工基准测试（Q1）。
2. 仅受支持的可调值外置，固有代码常量保留（Q2）。
3. Pipeline、Backend 各自使用 TOML，专用 TOML 保持独立（Q3）。
4. 密码放入 `.env`；`.env` 还可保存 Compose 宿主机挂载变量和 TOML 路径，其他
   非敏感运行配置进入 TOML（Q4、Q7）。
5. TOML 缺少任一已定义配置键即启动失败；Python 配置数据类无可调默认值（Q5）。
6. 每个进程入口只加载、校验一次，再显式传递不可变配置对象（Q6）。

7. 单次运行输入由 CLI/API 提供；会改变语义或执行行为的配置只来自 TOML（Q8）。
8. 每个服务一次读取一份完整 TOML，不提供配置叠加或逐键合并（Q9）。
9. 不考虑历史兼容，旧逐项环境变量和配置类 CLI 覆盖一次性移除（Q10）。
10. loader 校验键、类型、范围和跨字段关系，并一次汇总全部错误（Q11）。
11. 配置数据位于各服务顶层 `config/`；`src/` 只保留 loader、类型和业务代码（Q12）。
12. 使用标准库 `tomllib`、不可变数据类和集中 validator，不为 Pipeline 新增运行依赖
    （Q13）。
13. 实际生效的可调值进入 TOML；重复来源合并，死参数删除，运行上下文与配置拆分
    （Q14）。
14. Pipeline 持久化脱敏后的完整有效配置与摘要；Backend 只记录脱敏的路径、摘要和节
    （Q15）。
15. 配置仅在进程启动时加载；必须重启 Pipeline 才能重新加载（Q16）。
16. 默认 `processing_srid = 32649`，区域变化时换用另一份完整 TOML（Q17）。
17. Pipeline 与 Backend 采用按职责分节的固定 TOML 结构（Q18）。
18. 所有 Pipeline 生产 CLI 加载并校验同一份完整配置，再使用所需节（Q19）。
19. 测试从完整测试配置/fixture 构造场景，生产源码不提供默认配置工厂（Q20）。
20. 加入结构门禁，阻止 Python 默认值、散落环境读取、叶子 loader 和隐式默认配置
    回流（Q21）。
21. 新 Refine Run 使用 TOML 的 EPSG:32649；复用历史 Refine Run 时继承其持久化投影
    并明确记录来源（Q22）。
22. 仓库根目录 `.env` 只使用 `PIPELINE_CONFIG_PATH`、`BACKEND_CONFIG_PATH`、
    `POSTGRES_PASSWORD` 及 Q7 已允许的 Compose 挂载变量；不再搜索 package 内 `.env`
    或兼容旧变量名（Q23）。
23. 密码缺失/占位时服务和非交互 CLI 立即失败；只有显式 `--ask-password` 可在内存中
    接收交互密码（Q24）。
24. TOML 键就地记录用途、单位、范围和语义影响；同步部署文档并执行完整验证，删除旧
    package TOML 和旧逐项覆盖代码（Q25）。

设计树的功能分支已全部收敛；用户已通过 Q26 对完整 Spec 作最终设计确认。

## 6. 约束与非功能要求

- TOML 未知节、未知键、缺失键和错类型应失败，不得静默忽略或回退到 Python 默认值
  （Q5）；数值范围和跨字段验证强度待 Q11 确认。
- 密码通过 `.env` 注入，不得写入受版本控制的 TOML；`.env` 的其他允许内容仅为
  Compose 宿主机挂载变量和 TOML 路径（Q4、Q7）。
- 单次运行输入不得混入 TOML；TOML 配置不得被 CLI 或逐项环境变量覆盖（Q8–Q10）。
- loader 必须一次汇总缺键、未知键、类型、范围和跨字段关系错误（Q5、Q11）。
- 配置只在进程启动时加载，修改文件后必须重启 Pipeline；运行中的 Run 不得改变配置
  （Q16）。
- 自动门禁覆盖配置数据类默认值、TOML/schema 一致性、loader 导入、环境变量读取和
  `config=None` 隐式默认；同时保留人工参数清单审查（Q21）。
- 配置路径固定由根目录 `.env` 的 `PIPELINE_CONFIG_PATH` 和 `BACKEND_CONFIG_PATH`
  选择；文件缺失或不可访问时启动失败（Q23）。
- 密码及其他秘密不进入 TOML、日志、错误汇总、持久化快照或摘要原文（Q15、Q24）。
- 配置变更不得无意改变现有算法语义；迁移时需建立旧值到新 TOML 键的清单。
