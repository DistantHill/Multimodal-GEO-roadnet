## 1. 范围、背景与不变量

本次修复四类问题：

1. 公共 DB Detect 只接收调用者的 SpatialContext，未在计算前核对父 Clean Run。
2. DB 读取的 x/y 经 `trust_existing=True` 绕过数据范围及尺度验证。
3. 反投影窗口固定采样加一个浮点步长不能保证包围真实曲线，SQL 粗筛可能漏点。
4. 手动 cross-track 基准同时改变投影与实现，却比较完整记录精确相等，无法区分算法回归和投影行为变化。

当前 main 已有 schema v3 和 persisted-crossing Replay，不恢复 v1/v2 Replay 或旧数据原地迁移。
当前主 DB Detect 使用全局 tracks workspace 和空间索引；SQL 窗口主要服务诊断、基准。
不得把主 Detect 改回 SQL 滑动窗口，也不得改变其容量回退为内存窗口的契约。

| 用途 | 坐标契约 |
| --- | --- |
| 地理真值 | 一份 EPSG:4326 Geometry |
| Run 的计算、派生 x/y、算法输出 | clean_runs.processing_srid；Detect、Fit 继承 |
| 窗口构造和落窗判断 | 独立的标准 WGS84 / UTM 查询 CRS |
| 查询返回给算法的 x/y | 必须转换或保持为 Run processing CRS，不能泄漏 query x/y |

不新增数据库字段、验证缓存、空间上下文表、投影 Geometry 列、投影索引或迁移。
不修改历史 Run 的 CRS、坐标或数据；不 reset 数据库。
Run 的 `enforce_area_of_use` 和 `max_scale_error` 保持原有语义和配置，默认尺度阈值仍为 0.01。
全部运行逻辑留在 services/pipeline；不把计算移到 Backend，不做无关 UI 改动。

## 2. 正式 DB Detect 必须继承 Clean Run

### 2.1 入口与身份

- 正式 `detect_intersections(conn=..., query_active_from_db=True, ...)` 必须有 clean_id。
- 在范围查询、读点、提取候选等计算前，读取并验证父 Clean Run：存在、completed、合法且完整的投影上下文。
- 以 Clean Run 中保存的 source_table / 相关来源契约和 SpatialContext 为权威。
- 外部 SpatialContext 可以省略；若传入，只作为一致性断言，不允许覆盖父 Run。
- 调用者传入的 source/kept/table 参数不得指向不属于该 Clean 的来源；默认值与显式覆盖应作清晰区分，尽量从父 Run 派生。
- 空数据路径也必须先执行上述检查，不能用 early return 绕过。
- 保持已有来源 fingerprint、Run 状态和持久化完整性保护；不重复引入多次全来源扫描。
- 原始表直跑只允许通过明确命名的诊断/基准 API 或低层工具；不得在正式入口用宽松隐式 fallback 绕过 clean_id。
- 同步修改正式 pipeline 调用、相关测试和确有需要的手动工具；不只修持久化末端。

### 2.2 实际数据验证

- 复用已有读点流程，累计此次实际读取点（包括 injected）的经纬度范围。
- 检查非有限经纬度 / x/y 和非法地理域；随后使用父 Run 的规则检查区域与尺度。
- 全部结果返回或持久化前完成累计范围验证；失败不得产生成功 Detect 结果。
- 不能因为行已有 x/y 或 Clean 为 completed 就跳过检查。
- 不额外完整扫描一遍点表，不将 bounds / 校验标记落库，不新增整批点复制。
- 不跳过问题点、不偷偷改变 CRS、不放宽 Run 的阈值。
- 诊断 raw 入口使用显式 processing context，也必须有对应的数据合法性保护。

## 3. 最终窗口规则

### 3.1 窗口请求与独立上下文

- 窗口请求可用地理中心 `(lon, lat)` 和米制宽、高表达；最终矩形沿 query UTM 网格轴。
- 明确区分请求、选定的 query CRS、query x/y 矩形、真实地理边界及供 SQL 使用的保守 bbox。
- 现有 SpatialWindow 只有 Run x/y 四个数，不能把它直接改标为另一个 SRID。
- 可以增加独立的内存 QueryWindow/QueryContext 类型及显式适配器；命名可按代码习惯。
- 旧 Run 矩形适配时，先在原 Run CRS 求地理中心并保留其数值米制宽高，再按本规则重新构造；显式记录/文档说明地理轮廓会改变。
- 现有纯内存 SpatialWindowIterator 的 processing-CRS 语义保持不变；SQL 查询调用方必须显式适配。
- 拒绝非有限、非法中心、非正尺寸等非法请求。不支持或不能保证正确的极区、跨半球、反经线等情况须有明确错误，不得静默猜测或全世界 bbox 回退。

### 3.2 三度网格只限制跨度

采用前文讨论的常见三度网格：中央经线为 `3*n` 度，边界为 `3*n - 1.5` 度。
中国附近示例界线：`109.5 / 112.5 / 115.5 / 118.5 / 121.5` 度。

- 最多允许窗口实际进入两个相邻三度网格。
- 实际进入三个或更多网格时明确失败。
- 恰好触及分界线不算进入邻格；不能把触边当成覆盖第三格。
- 带数量由最终窗口完整地理覆盖范围决定，不是由点数据、仅中心、经度宽度或初选矩形决定。
- 窗口边界上的点仍按闭区间落窗规则返回。
- 三度网格不是 CRS，不生成“三度 UTM”、CGCS2000 或自定义 TM 投影。

### 3.3 选择最东 UTM 带与重建

- 查询实际使用标准 WGS84 / UTM 六度带，正确区分南北半球；不修改 UTM 的中央经线或比例参数。
- 选择最终窗口实际进入的最东侧 UTM 带。仅触及某带西边界不算进入该带。
- 同一窗口的所有点（包括位于左邻带的点）均使用同一个选定 query CRS。
- 可以从中心所在带初选，构造窗口并计算地理覆盖范围，再选择最东带。
- 带改变时保持原地理中心和米制宽、高，在新 query CRS 中重建矩形；不保留初选投影的旧轮廓。
- 必须以重建后的最终窗口复核：最东带与所选带一致、最多两个相邻三度网格、尺度和合法域满足要求。
- 选带需要有有界、确定的收敛/候选验证逻辑。循环、无一致解或无法确认正确时明确报错，不能无界迭代或默默选最后一次。
- 触边规则不得复用粗筛 bbox 的外扩值；否则 bbox 的安全 padding 会改变分带决定。区分真实边界估计、误差界和粗筛外包范围。

### 3.4 查询专用校验

- 允许窗口跨标准 UTM 经度带；不能直接套用 EPSG area-of-use 的经度范围来拒绝这种查询。
- 查询专用局部长度尺度误差上限为 `abs(k - 1) <= 0.015`（1.5%）。
- 仍验证地理域、UTM 可用纬度/半球、转换的有限性以及尺度误差；不能把“允许跨带”实现为关闭全部验证。
- 查询策略与父 Run 的 projection_config 分离，不能修改、复制后误传放宽过的 Run context 给算法。
- 本地 pyproj 的已核验参考值，EPSG:32649（中央经线111°），单位为 `(k-1)*1000`：

| 纬度 | 偏移3° | 偏移9° |
| --- | --- | --- |
| 0° | 0.981062 | 12.145707 |
| 30° | 0.633517 | 8.948546 |
| 45° | 0.287498 | 5.792657 |
| 60° | -0.057005 | 2.676853 |

9° 赤道的约 1.2146% 可以通过查询尺度策略，但仍必须单独满足三度网格跨度约束；不能把表格示例直接当成合法完整查询。

### 3.5 SQL 粗筛与精筛

- 从 4326 Geometry 生成可靠的保守粗筛 bbox，继续使用已有 Geometry GiST。
- 原始点与 injected 都应从各自 4326 Geometry 转到同一个 query CRS，以数值闭区间比较 query x/y 判断落窗。
- 精筛使用窗口原始双精度数值界限，不用 epsilon 或 ULP 外扩扩大成员集合；向外舍入只用于保守粗筛外包。经反投影再正投影的名义边界点可能因浮点舍入不再恰等于边界，验收以实际 `ST_Transform` 数值及不带粗筛的独立谓词为准，不能为使该类 fixture 通过而放宽生产精筛。
- 不得拿 injected 已存 Run x/y 与 query 矩形直接比较。
- 查询输出的原始点 x/y 使用 Run processing CRS；injected 可使用经 Run 身份验证的已存 Run x/y，或从 Geometry 转到 Run CRS。
- 保持来源身份、clean 隔离、稳定次序、subtrack / resolved 点引用和现有 telemetry 契约。
- 查询参数安全绑定，表标识符继续使用现有合法性验证；不接受任意用户 SQL/PROJ 字符串。
- 不增加或持久化第二份 Geometry；使用 ST_Transform 真正变换，不用 ST_SetSRID 冒充变换。

### 3.6 不漏点保证与失败策略

- 尺度畸变可接受不等于粗筛漏点可接受，1.5% 不是 bbox padding 或浮点容差。
- 原有 fixed densify=64 + nextafter 不合格；仅增大采样数、比较两轮采样是否收敛、任意固定 epsilon，也不能单独声称获得保守保证。
- 为支持的 UTM/TM 窗口给出有依据的边界极值/导数误差界或其他可靠外包方法，并在文档说明适用域及浮点外扩。
- 最低应覆盖完整四条曲线边界、中央经线经过矩形时的边内极值、南北半球及跨带场景；不能只验证四角。
- 无法可靠外包或违反支持条件时明确失败，不静默使用全域 bbox、全表精筛或近似漏点结果。
- 通用 CoordinateTransformer.inverse_bounds 若仍公开，不得让其旧的不安全路径悄悄保留“保守”承诺。支持的投影正确处理，不支持的显式拒绝或把安全查询职责移入专门 API 并清晰限制旧 API。

已复现的不安全旧实现：EPSG:32650 矩形 `(250000,4300000,750000,4400000)`，旧 bbox 北界为 `39.74989883744608`。
点 `(500000,4399999.9)` 的纬度约 `39.749906618085376`，在矩形内但在旧粗筛外；即使考虑 PostGIS float32 bbox 外扩仍可能漏点。
新的受支持路径必须包围它；如果窗口策略判其非法，应在 SQL 执行前明确拒绝，不能继续查询并漏点。

## 4. 两套独立的基准与报告

### 4.1 同 CRS 算法等价 / 性能门禁

- 冻结相同输入点集、参数、查询窗口及 CRS，只更换 dense/reference 与 optimized 算法实现。
- reference 的线段端点也须先投影到相同 processing CRS 再求交；不能求 legacy 交点后仅把结果点转换到新 CRS。
- 保留历史 local-origin oracle 给投影差分使用，不冒充同 CRS oracle。
- 来源关系、候选身份、成员、规定的稳定顺序和聚类成员严格比较；不一致则失败。
- 数值逐字段以单位明确的容差比较并报告差值，不能比较整个 as_dict 精确相等，也不能只比较数量。
- 浮点误差预算与查询 1.5% 独立；建议同 CRS x/y 从绝对 `1e-6 m`、lon/lat 从 `1e-9 degree` 量级起验证，必要调整必须有证据并写入报告，不采用随百万级坐标放大的宽松相对容差。
- 不改变/弱化已有最少点数、重复次数和性能门禁以制造通过。小样本只能证明功能，不能宣称达到 500k/1m 性能门禁。
- 修复并实际接通 manual_bench_cross_track_inner 或等效可执行入口，不只新增未被使用的比较函数。

### 4.2 legacy → fixed CRS 差异评估

- 独立于同 CRS 性能门禁，输入来源和算法变体必须可追溯，报告旧投影与新投影的影响。
- 提供可执行报告入口；允许读取冻结的 legacy/new 快照，不要求在 v3 数据库复活 v1/v2 schema。
- 比较来源身份对应点的坐标位移分布（数量、分位数、最大值）、候选新增/缺失、cluster membership、Clip 有序成员、长度和拟合几何变化。
- 地理坐标应变换到明确的共同米制比较空间或用明确的椭球距离比较，不能把经纬度差当米，也不能直接相减不同 CRS 的 x/y。
- 对未提供/未计算的阶段，明确标记 not_evaluated；不能以空列表或零差异伪称全链路稳定。
- 支持捕获当前结果或明确的快照 schema/适配接口；使用确定性 fixtures 覆盖包含 Clip/Fitting 的报告行为。
- 不因存在正常坐标差异立即中止，先输出完整可审计差分报告。
- 报告记录输入/结果哈希、CRS（包括查询规则版本）、参数、版本、容差及验证覆盖范围。
- 首次基线及任何结构性变化默认 pending_review；人工明确接受后才允许更新基线，不能由性能测试、正常运行或 --write-report 隐式批准。
- 人工接受须绑定具体报告/输入哈希，记录接受信息；不能用一个无来源的 accepted=true 代替审批。
- 当前实施可以提供显式接受命令/API 与测试，但不得替用户接受真实新基线。

已复现的旧门禁误报：两条线段 `(115.999,39)-(116.001,39)` 与 `(116,38.999)-(116,39.001)`，legacy origin `(116,39)` 对比 fixed EPSG:32650，候选均为1个但交点约相差 `0.0004758634 m`。这应进入投影差异报告，不应混入同 CRS 算法等价门禁。

## 5. 必须覆盖的验收矩阵

### A. 入口 / Run

- 无 clean_id、未知/未完成 Clean、缺少或非法 CRS、显式上下文不匹配、错误来源均在读点前失败；空数据也不绕过。
- 有效 Clean 可不传重复 SpatialContext，返回结果上下文与父 Run 一致。
- DB 点已有 x/y 时仍能发现越界、尺度超限、NaN/Inf；验证包括 injected，且无重复全点扫描。
- 内存 Detect 原行为、Run strict area/1% 校验、pipeline 生命周期和 fingerprint 保护不回归。

### B. 窗口 / SQL

- 单带、跨两个三度网格、实际进入第三格拒绝；三度边界及 UTM 边界的 just-inside/exact-touch/just-outside。
- 标准 UTM 带选择正确，最东带取决于最终窗口且触边不算；不能按数据点带号选。
- 切带后中心和米制宽高不变，重新验证最终 footprint；无解/循环有界失败。
- query 1.5% 与 Run 1% 独立；跨 EPSG 经度 area 不直接拒绝；非有限、极区或不支持边界明确失败。
- 反投影边内极值及上述旧 bbox 漏点复现；不以少量采样测试代替边界方法依据。
- 原始点和 injected 地理同点、Run CRS 与 query CRS 不同的真实 PostGIS 查询，二者成员一致且返回的是 Run x/y。
- 窗口边界点包含、窗外紧邻点排除（精筛不能仅依赖 Geometry bbox 的低精度 overlap）。
- 用不带粗筛的独立精确谓词作测试 oracle，对随机/边界样本验证有粗筛查询无 false negative；生产代码不增加慢扫描 fallback。
- 原 SQL 窗口 manual 调用迁移、全局 Detect 与内存窗口回退测试保持通过。

### C. 基准 / 文档

- 同 CRS：tiny roundoff 可报告并按阈值通过；来源/成员/顺序错误即使数量相同也失败；非有限数值失败。
- 投影差分：正常非零位移生成报告；候选/cluster/Clip 结构变化触发 pending；缺失阶段 not_evaluated。
- 未经明确审批不能接受或覆盖基线；审批记录绑定哈希；哈希不匹配拒绝。
- 文档说明新入口、双 CRS、选带/触边、失败条件、支持域、两套运行命令与报告局限。

## 7. 已废弃方案（禁止误实施）

- 不再使用“三度投影，跨两带后以分界为中央经线创建自定义六度 TM”。
- 不把三度网格等同于标准 UTM CRS。
- 不因跨 UTM 经度带本身就拒绝；拒绝条件是三度跨度、查询尺度/支持域或无法保证正确。
- 不把“允许最多两带”扩展成两个 UTM 六度带；保留的是两个相邻三度网格。
- 不给 Run 放宽为 1.5%，不把 query CRS 放到父 Run 或持久化派生行。
- 不只给旧结果 x/y 做变换后继续 exact equality 比较两个投影。
- 不自动接受投影基线，不修改旧数据，不恢复旧 schema。
