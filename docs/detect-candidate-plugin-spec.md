已核查事实（2026-10-09）：
- 普通 Detect 有两个启用开关；实验额外枚举候选和聚类算法名称。
- 聚类输入、报告及持久化绑定 turn/cross 两类证据。
- 实验配置有基础值与覆盖；恢复原样输出 draft_snapshot，没有结构迁移。
- 既有配置集中化禁止 Python 可调默认值。插件参数类型校验而不补可调默认值。

2026-10-10 新核查：
- Refine reader 先从完整输入形成窗口和转向角，再按最小角度筛选；同输入与其他提取参数、只改变最小角度时，较严格阈值结果是较宽阈值结果的子集。
- turn_threshold 最终边界为 abs(turn_deg) > min_turn_deg；不能改为 >=。
- SQL 在筛选后生成 calculation_index，独立计算与从父集合筛选的行编号可能不同；来源引用与实例局部编号应分离。
- 当前评价针对 Detect 最终交叉口，支持 precision/recall/f1 等；尚无按算法实例归组的排名接口，历史列表是分页的。Top N 不能靠排序当前列表页实现。

## 3. 需求与使用场景

顶层 candidates 选择算法，如 turn_threshold、cross；参数调优由算法层组织。turn_threshold 下 params 持有 turn_30、turn_60 等具名参数集合，不再把这些实例提升为 detect.candidate 下的顶层节点（Q17 批注 1、2）。
用户在算法内部寻找独立聚类表现较好的参数，再按指标选 Top N 送入后续消融；不自动遍历所有算法参数的笛卡尔积（Q14、Q16）。

前端目标：历史结果按算法组织，在详情地图上方显示该算法 1 至 n 个实例选项；点击显示对应参数结果；Top N 选项背景高亮。当前选中与 Top N 应可分别表达，具体样式尚未实现。排名指标、比较范围、同分/缺失评分规则尚未确认，不将示例 n=2 固化。

## 4. 方案与关键决策

注册表提供算法能力与参数类型；唯一运行器按 TOML 选择算法。插件拥有整组参数实例的执行计划和输出，不认识其他算法结果。默认可逐实例计算；具有已证明子集关系的插件内部复用。

Q17 更正此前 Q14 的 TOML 示例：
- 保留“算法与参数实例分离”的概念。
- 否定 [detect.candidate.turn_30] + plugin 的实例平铺表达。
- 改为 [detect.candidate.turn_threshold] 下 params 中维护具名实例。
- 顶层 candidates 只包含算法 ID。

有效执行语义：
- 候选插件与参数实例顺序调度；已有算法内部线程能力保留（Q12）。
- 插件失败使所属 Detect 失败，不发布缺来源的成功结果（Q11）。
- 跨算法输出只拼接，重复保留（Q15）；同算法不同参数复用中间结果不违反算法间隔离。
- 子集复用仅影响计算量，不复用聚类标签；各参数独立评测时仍按各自候选重新聚类。

Q20 已确认第 2–8 节完整设计并授权实施。未来界面和自动 Top N 的指标、比较范围、并列处理及消融组合属于后续范围，不阻塞本次。

已确认的实施细则：专用候选/聚类插件包自动发现显式描述对象；稳定算法 ID 唯一，重复注册或配置引用不存在即报错。模块导入不启动计算。配置启动时集中解析与校验，再传给执行器；执行器不维护具体算法清单或参数默认值。

## 5. 接口、数据与架构影响

已确认结构的有效 TOML 表达示意（省略其余必填参数）：

```toml
[detect]
candidates = ["turn_threshold", "cross"]
cluster_algorithm = "dbscan"

[detect.candidate.turn_threshold]
output_instances = ["turn_30"]

[detect.candidate.turn_threshold.params.turn_30]
min_turn_deg = 30.0

[detect.candidate.turn_threshold.params.turn_60]
min_turn_deg = 60.0
```

上述 params 是具名实例映射，算法 ID 直接对应注册项，无需每个实例重复 plugin。示例省略 cross 的完整实例配置、聚类参数及其他必填字段，不可直接作为运行配置。

聚类每次选择一个算法，如 cluster_algorithm="dbscan"，参数按 [detect.cluster.dbscan] 的 params 表提供；本次不增加聚类参数组合搜索。候选首批适配现有角度筛选、G* 筛选和跨轨迹计算；聚类适配现有 DBSCAN/HDBSCAN，保持各自原有语义。
output_instances 是必填的算法内部输出选择，引用本算法 params 的实例名；按该列表顺序输出，按顶层 candidates 顺序拼接。正常运行不自动将所有 params 合并，也不自动排名（Q19）。多个选中实例即使重叠仍保留全部候选行（Q15）。

建议接口：
- 候选插件接收本算法参数实例集合、本次请求的实例集合与运行上下文，返回按实例索引的候选结果句柄。普通运行请求 output_instances；独立评测请求相应实例，各自聚类并关联参数与运行结果。
- 插件可在内部制定共享提取和筛选计划；不让中央编排器硬编码 turn_threshold 等优化规则。
- 结果保留算法 ID、实例 ID、实例局部候选 ID、底层来源引用与输入范围。
- 统一输出声明 candidate_points；不支持的输出类型运行前报错，不自动转换。
- 普通运行只导出 output_instances（Q19）；未选中的实例不进入聚类。插件内部只计算本次请求所需的结果及复用中间产物，不因 params 中有其他配置就运行无关实例。

子集复用建议：
- 同一次调用、同一 Refine/有效时间范围/投影，其他提取参数一致，只改变 min_turn_deg 时，在本次请求中先计算最小阈值实例，再筛选得到其他实例；共享候选用于独立评测时，每个实例分别重新聚类。首版不增加跨运行持久缓存。
- 保留严格 > 边界、源点引用、候选顺序；按实例管理编号，不要求父子 calculation_index 天然相同。
- turn_window 改变会改变角度，不能套用筛选复用。其他无证据支持的参数关系独立计算，不从实例名称猜包含关系。
- 如存在多个互不包含参数组，插件内部各自建立复用组，不强行假定存在一个覆盖所有实例的最大集合。
- 复用结果使用列式或磁盘关系句柄，避免保留多份全部候选 Python 对象。
这些是依据代码的实施细则，已随 Q20 确认；子集复用需求本身已经用户明确提出。

配置校验：未知算法、重复 ID、未知参数、非法类型/范围、缺必填参数、空 candidates、空 output_instances 或不存在的实例引用，在计算前报错。合法运行产生零候选是有效空结果，不冒充插件失败。

存储适配：聚类通用层只消费统一点候选与实例身份；turn/cross 证据保存差异由适配层承接。保留现有最终交叉口、拓扑与导出语义，记录完整有效参数和选择。算法/实例归属应贯通候选、统计与实验归档，为后续界面提供数据。加入新算法若使用已有证据接口，无需修改中央编排；全新证据形态仍需适配，不承诺任意结构零改动落库。

资源所有权：Detect 执行上下文管理中间结果，在聚类、现有消融和持久化消费完成后关闭；异常路径统一清理。候选结果允许多次扫描，供消融复用，不反复执行候选生成。现有来源消融以带算法/实例身份的来源组重新聚类，保留其既有分析性质，不视作自动 Top N 实验生成。

## 6. 约束与非功能要求

沿用 Pipeline 计算边界、仓库外运行数据及 SQL 索引审查要求。顺序执行避免多插件并发争用内存，但仍需管理已产出结果的生命周期。

## 7. 验收标准

已有明确要求：
- 顶层选择算法，各算法下配置多个参数实例。
- 普通候选输出保留来源，不做跨算法 diff/去重；重复输出计数保留。
- 符合子集关系的 turn_30/turn_60 只做一次共同提取；子集筛选保持严格边界和来源。
- 不具有已支持关系的参数组独立计算，不错误复用。
- 插件间顺序执行，插件失败导致所属 Detect 失败。

Q20 已确认的具体验证：
- 新增符合接口的插件只需新增插件模块并配置算法，不修改中央名称清单或聚类分支。
- 检验非法配置和不支持输出类型在计算前失败；合法零候选返回空结果。
- 同一算法有多个 params 时，普通运行仅拼接 output_instances；各算法、实例顺序确定，来源完整。
- 优化结果与各实例独立计算等价，比较证据、坐标与排序，不要求偶然行编号一致；覆盖严格角度边界、窗口变化不复用及多个不相容参数组。
- 相同事件跨实例重复输出保留多行，运行链路没有跨算法 diff/去重。
- 验证只提取一次公共候选、子集派生、实例独立聚类、重复扫描和异常清理。
- 等价旧配置迁移后保持候选、簇成员、拓扑和来源追溯语义；旧历史快照原样保留，显式转换生成新配置，无法补全的必填项明确报错。
